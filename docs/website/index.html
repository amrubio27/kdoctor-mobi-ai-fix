// FEATURES

Lo que trae la v1 — y por qué cada pieza importa

01 · Análisis

AST analysis puro

Recorremos el AST de .kt/.kts sin JVM, en paralelo con Detekt, Lint y KtLint. Cero LLM tokens por escaneo.

02 · Score

Health Score 0–100

Ponderado por severidad. Compara dos proyectos, gamifica la refactorización, bloquea CI limpio.

03 · AI Fix

Agnóstico al LLM

Claude Code, Cursor, Gemini CLI, Copilot o MobiAI. Tú eliges. Ningún vendor lock-in.

04 · CI

SARIF + GitHub Scanning

Salida SARIF 2.1 nativa. Tus findings aparecen inline en cada PR de GitHub. Sin servidor extra.

05 · Hooks

Pre-commit / pre-push nativo

adkd hook install --fail-below 80 y olvídate de merges que rompen score.

06 · Extensibility

Rule-packs enchufables

Como shareable configs de ESLint. Publica tu pack en npm o GitHub. La comunidad los adopta.

07 · Reportes

HTML dashboard estático

Un index.html que GitHub Pages sirve gratis. Tendencias por archivo histórico.

08 · MobiAI

Instalable como skill

mobiai skills install adkd. Se enchufa al Graph semántico de MobiAI.

09 · Tipos

KMP + CMP nativos

Reglas para commonMain, expect/actual, Compose Multiplatform estable.

Una pieza que falta en el ecosistema MobiAI

MobiAI ya inyecta contexto mobile en tu IA favorita. adkd le añade el único ingrediente que le faltaba: un motor de reglas estáticas con Health Score.

Nivel 1

Skill instalable

mobiai skills install adkd
Descarga el binario, registra el wrapper mobiai doctor --code.

Nivel 2

Provider de findings

Graph semántico de MobiAI se enriquece con cada scan. Los issues aparecen como anotaciones en el archivo cuando la IA trabaja.

Nivel 3

Fixer automático

La IA que MobiAI ya trae configurada se convierte en fixer. Cero configuración extra, cero vendor lock-in.
